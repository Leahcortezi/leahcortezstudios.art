## Overview

Leah's case study pages (`collections/<category>/<slug>/index.html`) are generated by `scripts/rebuild-case-studies.js` into one rigid five-section layout: Brief → Research → Sketches → Concept → Details. Every section is a rounded card, every section looks the same, and the script stamps the same boilerplate copy into every page (`sectionCopy()`), plus five empty "Application placeholder" tiles.

This redesign replaces that with a **set of blocks that can be mixed and matched per project**:

- Required on every page: **Hero** (split or wide), **Overview** (Challenge / Solution / Outcome), **Next**.
- Optional, any order, repeatable: **Story**, **Feature (full-bleed)**, **Gallery**, **Process strip**, **Motion**.
- No cards. Sections sit directly on black, separated by space and thin pink rules. The Overview is a full-width pink band, the one colour moment on the page.
- No boilerplate. A field that's empty renders nothing. A block with nothing in it renders nothing.
- New fields: Role, Tools, image captions, Challenge / Solution / Outcome.

The worked example is **Insane Grain / Snack Packaging** (`collections/design/insane-grain-packaging/`).

## About the design files

The files in `design/` are **design references built in HTML**: a prototype showing the intended look and behaviour, not production code to copy. `design/Case Study Template.dc.html` runs in a design tool runtime (`support.js`), uses inline styles everywhere, and uses an `<image-slot>` drag-and-drop component for images. **None of that belongs in the site.**

The task is to **recreate the design in the existing site's environment**: plain static HTML pages, global CSS in `css/`, and the Node generator in `scripts/`. To make that easy, `reference/` contains a site-native version already written against the repo's conventions:

## Things in the existing code to watch for

- `css/styles.css` sets `h1–h6 { color: #f8c8d0 !important; margin-bottom: 1rem; letter-spacing: 1.5px; line-height: 1.3 }`. The v2 CSS resets margin, line-height and letter-spacing inside `.cs-page`, and overrides colour with `!important` only where headings must not be pink (the Overview band).
- `styles.css` styles **every `<nav>` element** as the sticky site bar (sticky, 80 px tall, black, pink bottom border, flex). The old `<nav class="case-study-next">` inherits all of it, which is why the live prev/next row has a stray line under it. `nav.cs-next` in the v2 CSS undoes this. Keep that reset if you change the element.
- `styles.css` sets `img { height: auto; max-width: 100% }`. Images inside `.cs-media` are absolutely positioned at `width/height: 100%` with `max-width: none`.
- `styles.css` sets `p { margin-bottom: 1rem }` and, at ≤768 px, `p { font-size: .9rem }`. The v2 classes set their own sizes and `.cs-page p { margin: 0 }`, so type doesn't shrink on mobile. That's intended: 17 px body text on phones.
- `work.css` gives `.case-study-page` `max-width: 1180px` plus padding. **Keep the `case-study-page` class on `<main>`**, because `page-enhancements.js` only adds the scroll-progress bar when it finds `.work-page, .case-study-page`. Add `cs-page` alongside it. `.case-study-page.cs-page` removes the max-width so Feature and Overview can run full-bleed.
- **Prev/next links are currently dead on case study pages.** They're `href="#"`, and `navigation-randomizer.js`, which fills them in, isn't loaded there. The new generator should compute real hrefs at build time from the gallery order. Move the `galleryOrder` array out of `scripts/navigation-randomizer.js` into a shared `scripts/gallery-order.json` and read it from both. Keep the classes `prev-work`, `all-work`, `next-work`, because `main.js` uses `.prev-work`/`.next-work` for ←/→ keyboard navigation. The order wraps around (first ↔ last).
- Don't load `css/case-study.css` on these pages. It has its own `.case-study-section` card and fade-in styles from an older version.
- `page-enhancements.js → initApplicationGridFix()` only touches `.case-study-application-layout`, which the new markup doesn't use. It's harmless and can be left in.
- **Breadcrumb:** the generator emits a `<div class="breadcrumb">`, but the live Insane Grain page doesn't show one, and the design has none (the "← Work" link covers it). Leave it out of v2 pages. Ask Leah if she wants it back.

## Data schema: `case-study.json`

All text is plain text. HTML-escape it when rendering. All paths are relative to the page folder. **Every field is optional except `title`.** Missing fields render nothing (no fallback copy, ever).

```jsonc
{
  "title": "Snack Packaging",              // h1
  "category": "Packaging",                 // kicker: "Case study · {category} · {year}" (omit missing parts)
  "year": "2025",
  "summary": "…",                          // hero lead + <meta name="description">
  "meta": [["Role","…"],["Tools","…"],["Year","2025"],["Deliverables","…"]],  // any labels, any count; rendered in order
  "hero": { "layout": "split" | "wide", "src": "images/cs/hero.jpg", "alt": "…", "poster": "…" },
  "overview": { "challenge": "…", "solution": "…", "outcome": "…" },   // each optional; band omitted if all empty
  "blocks": [
    { "type": "story", "imageSide": "right" | "left", "label": "01 — Research", "heading": "…", "body": "…",
      "src": "…", "alt": "…", "ratio": "864/604", "caption": "…" },
    { "type": "feature", "label": "03 — Final", "src": "…", "alt": "…", "caption": "…" },
    { "type": "gallery", "layout": "justified" | "grid", "label": "…", "heading": "…",
      "items": [{ "src": "…", "alt": "…", "ratio": "736/979", "caption": "…" }] },
    { "type": "process", "label": "…", "heading": "…",
      "steps": [{ "src": "…", "alt": "…", "title": "Research", "caption": "…" }] },
    { "type": "motion", "label": "…", "heading": "…", "body": "…", "src": "loop.mp4", "poster": "loop.jpg", "alt": "…", "caption": "…" }
  ],
  "prev": "…", "next": "…"                 // optional overrides; default is computed from gallery-order.json
}
```

Rendering rules:

- **Media type by extension.** `.mp4/.webm/.mov` → `<video autoplay muted loop playsinline preload="metadata" poster="…">`. Reuse the `.mov` → `.mp4` companion-source logic from `makeMediaPlaceholder()` in the old script. Otherwise use `<img>`. The hero image gets `fetchpriority="high"` and no lazy loading. Every other image gets `loading="lazy"`.
- **`ratio`** sets `style="--ratio: W / H"` on `.cs-media`. If it's missing, read the image's pixel size (write a tiny JPEG/PNG header reader; don't add an npm dependency) and fall back to `3 / 2`. For justified galleries, each item also gets `style="--grow: {W/H to 3 decimals}"`, which is what makes a row share one height.
- **`alt` is required for every image.** The build should warn, not fail, when one is missing.
- **Story `imageSide`** changes DOM order: `right` = copy then figure; `left` = figure then copy. Default `right`. When a page has consecutive Story blocks, alternate sides.
- Omit `.cs-label`, `.cs-h2`, `.cs-body` or `figcaption` elements when their field is empty. Omit a block entirely when it has no media and no text.
- `meta` renders as `<dl class="cs-meta">` with one `<div><dt/><dd/></div>` per pair.
- Overview: render only the items that have text. The grid reflows on its own.

## Block markup

Exact markup is in `reference/collections/design/insane-grain-packaging/index.html`. Blocks the example doesn't use:

```html
<!-- Hero · wide -->
<header class="cs-hero cs-hero--wide cs-wrap">
  <a class="cs-back" href="../../index.html">← Work</a>
  <div class="cs-hero-top">
    <div class="cs-hero-intro"><p class="cs-kicker">…</p><h1 class="cs-title">…</h1></div>
    <p class="cs-lead">…</p>
  </div>
  <dl class="cs-meta">…</dl>
  <div class="cs-media cs-hero-wide-media"><img …> or <video …></div>
</header>

<!-- Gallery · grid (uniform 4:5) -->
<section class="cs-block cs-gallery cs-gallery--grid cs-wrap">
  <div class="cs-block-head"><p class="cs-label">…</p><h2 class="cs-h2">…</h2></div>
  <div class="cs-gallery-row">
    <figure class="cs-gallery-item"><div class="cs-media"><img …></div><figcaption class="cs-caption">…</figcaption></figure>
    …
  </div>
</section>

<!-- Process strip -->
<section class="cs-block cs-process cs-wrap">
  <div class="cs-block-head"><p class="cs-label">…</p><h2 class="cs-h2">…</h2></div>
  <ol class="cs-process-list">
    <li class="cs-process-step">
      <div class="cs-media"><img …></div>
      <div class="cs-process-meta"><span class="cs-process-num">01</span><span class="cs-process-text">{title} — {caption}</span></div>
    </li>
  </ol>
</section>

<!-- Motion -->
<section class="cs-block cs-motion cs-wrap">
  <div class="cs-block-head cs-block-head--split">
    <div><p class="cs-label">…</p><h2 class="cs-h2">…</h2></div>
    <p class="cs-body">…</p>
  </div>
  <figure class="cs-motion-figure">
    <div class="cs-media"><video autoplay muted loop playsinline preload="metadata" poster="…"><source src="…" type="video/mp4"></video></div>
    <figcaption class="cs-caption">…</figcaption>
  </figure>
</section>
```

Process numbers are generated (`01`, `02`…). The text is `{title} — {caption}`, or just whichever field exists.
