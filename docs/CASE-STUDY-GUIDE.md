# Case study guide

How to fill a case study so every page reads in the same voice. Put this file in the repo (e.g. `docs/CASE-STUDY-GUIDE.md`) and write each `case-study.json` against it.

## Required vs optional

Required on every page: **Hero** (split or wide), **Overview**, **Next**.
Everything else is optional. If you can't fill a block honestly, leave it out. Never pad.

## Blocks

| Block | Use for | Image spec |
|---|---|---|
| Hero · split | Objects and portrait work: packaging, posters, illustration | Square, 1600px+, ideally the piece on black |
| Hero · wide | Landscape work: web, motion, spreads, brand systems | 16:9, 2400px+ (image or MP4) |
| Overview | Challenge / Solution / Outcome. If you can only fill one, fill Challenge. | — |
| Story | One per stage worth showing: research, sketches, concept, refinement. Alternate image right / left. | Any ratio; set `ratio` |
| Feature · full-bleed | Your single strongest shot, edge to edge | 2:1 crop, 2400px+ |
| Gallery · justified | 2–3 images that share one row height (mixed ratios are fine) | Set `ratio` per image |
| Gallery · grid | 3-up uniform tiles | Crops to 4:5 |
| Process strip | When the process matters but doesn't need a paragraph per step. 3–5 frames. | Crops to 1:1 |
| Motion | Animated logos, titles, loops. Under 20 s, muted. | 16:9 MP4 (+ poster JPG) |

## Recipes by work type

| Work type | Order |
|---|---|
| Packaging | Hero split → Overview → Story ×2 → Feature → Gallery justified |
| Branding | Hero wide → Overview → Story → Gallery grid → Feature |
| Posters & print | Hero split → Overview → Feature → Gallery grid → Story |
| Illustration | Hero split → Overview → Gallery justified → Process |
| Motion | Hero wide → Overview → Motion → Process |
| Web / digital | Hero wide → Overview → Feature → Story ×2 → Gallery grid |

## Voice: personal, specific, honest. Made to linger, not to please.

1. **Write as yourself.** "I pulled collage portraits…", not "The designer conducted research…"
2. **Name the specific thing.** "A halftone mouth and real chilies", not "bold, eye-catching visuals".
3. **Cut anything generic.** If a sentence could sit in anyone's case study ("research gathers references"), delete it.
4. **One idea per sentence.** Short beats clever. If it needs two commas, make it two sentences.
5. **Honest over impressive.** Say what changed, what didn't work, what you'd push next. No numbers you can't back up.
6. **Same order every time.** What it is → why it needed to exist → how you got there → what exists now.

## Word budgets

| Field | Budget |
|---|---|
| Hero summary | 30–50 words |
| Challenge, Solution, Outcome | 15–35 words each |
| Story text | 40–80 words |
| Headings (sentence case) | ≤ 6 words |
| Captions | ≤ 12 words |

## Sentence starters

- **Summary:** "___ is a ___ for ___. I wanted it to feel ___."
- **Challenge:** "The problem was…" or "___ needed…"
- **Solution:** "I made… The big idea was…"
- **Outcome:** "The final set includes…" or "Now it…"
- **Story:** "I looked at… and noticed…" or "The first version… so I…"
- **Caption:** "What it is: one detail worth noticing."

## Labels

- Stage labels are numbered in page order: `01 — Research`, `02 — Sketches`, `03 — Final`…
- Kicker is always `Case study · {Category} · {Year}`.
